  exerc      made to fire by at least one case

  unreach    of those, PROVEN impossible. Human-reviewed only; a corpus

             empty by construction.

  Reported, NOT gated. Gating on this before the published rulesets are
  executed would gate on the wrong denominator.

  session by XML parse, not grep:

  979 DOES NOT DOUBLE-COUNT.
    EN16931-UBL-validation-preprocessed.sch carries 979 assert nodes
    across 3 patterns (UBL-model 201, UBL-syntax 756, Codesmodel 22)
    with 979 DISTINCT @id values and zero repeated IDs.
    EN16931-UBL-codes.sch is a byte-equivalent duplicate of the
    Codesmodel pattern already inside the preprocessed file — all 22
    assertions match on (@id, @context, @test) exactly. Summing the two
    files would give 1001; 979 is the preprocessed file alone and is
    therefore already free of that duplication. No restatement required.

  303 DOES NOT DOUBLE-COUNT.
    trn-invoice/ and trn-creditnote/ are byte-identical to each other on
    both file pairs (preprocessed 171 each, jurisdiction-aligned 132
    each; invoice-only = 0, creditnote-only = 0 on both). Summing all
    four files would give 606. 303 = 171 + 132 is the deduplicated
    figure and is correct.


3. A THIRD COPY OF EN 16931 IS VENDORED — and 1,301 does not reconcile
----------------------------------------------------------------------
  peppol-bis-3.0/published/CEN-EN16931-UBL.sch also carries 979
  assertions and shares 978 rule IDs with
  en16931/published/EN16931-UBL-validation-preprocessed.sch. The two
  differ by exactly one ID each way:

      only in en16931/published : UBL-SR-56
      only in peppol/CEN        : BR-CO-25

  So EN 16931 is vendored twice under two profiles. Any denominator that
  sums across profile directories double-counts ~979 assertions.

  Measured union of all distinct published rule IDs across the vendored
  tree = 1442.
      en16931 979 + pint-ae 303 + peppol-specific 159 = 1441
      (the 1-rule gap is the UBL-SR-56 / BR-CO-25 divergence above)
      naive sum of every published .sch file            = 2420

  RULES.md states the hand-authoring burden as "1,301 published rules".
  That figure reconciles with none of the measured combinations. It is
  ~140 LOWER than the true distinct count, i.e. wrong in the direction
  that makes the blocked work look smaller than it is. RULES.md is 🔒 —
  correction proposed as a diff in rules-md-defects.patch, not applied.
